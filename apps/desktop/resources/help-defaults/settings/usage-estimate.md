# Settings: API usage estimate

Configure pricing inputs used to estimate token spend.

This page controls global usage estimates. Per-project budgets and project usage reports are managed from **Project Management**.

## When To Use It

Use this section when cost estimates are missing, usage appears unpriced, provider pricing changed, or you need to set input hit, input miss, and output prices.

## Quick Steps

1. Open **Settings > API usage estimate**.
2. Choose the currency.
3. Add or edit the provider/model pricing row.
4. Enter input hit, input miss, and output prices per 1M tokens.
5. Set the effective-from date.
6. Save and check the usage estimate on the main page or Project Management.

## Step-By-Step: Fix Unpriced Usage

1. Identify the provider and model used by the task.
2. Open the matching pricing row.
3. Add input hit, input miss, and output prices.
4. Set an effective-from date that covers the task date.
5. Save the row.
6. Reopen the usage view and confirm the estimate appears.

## Key Settings

- **Currency**
  - Global currency for display.
- **Provider/model pricing rows**
  - Input hit price per 1M tokens.
  - Input miss price per 1M tokens.
  - Output price per 1M tokens.
  - Optional effective-from date.
- **Inherited pricing**
  - Model-level rows can inherit provider-level defaults.
- **Usage summary**
  - Shows token totals and estimated cost for the selected period.
  - Uses provider-reported token details when available.

## Token Cost Fields

- **Input hit**
  - Cached input tokens that the provider billed at the cache-hit rate.
- **Input miss**
  - Non-cached input tokens, or cached input tokens billed at the miss/write rate.
- **Output**
  - Tokens generated by the model.

Different providers name these fields differently. The app maps known provider usage fields into input hit, input miss, and output where possible.

## Purpose

This section affects estimate/reporting displays. It does not change provider billing.

The estimate can differ from the provider dashboard when:

- Provider usage reporting is delayed.
- A model did not return cache hit/miss details.
- A pricing row is missing, inherited, or effective from a different date.
- Provider dashboards include credits, taxes, minimums, rounding, or non-token charges.
- The app is showing a different date range from the provider dashboard.

## Project Budgets

Open **Project Management** to create usage projects and budget windows.

- Tracking-only projects group costs without enforcing a budget.
- Budget windows can warn or block when money or total-token limits are exceeded.
- Project reports show input hit, input miss, output, total tokens, and cost breakdowns.

## Tips

- Use official pricing docs for each provider/model.
- Set effective dates when pricing changes over time.
- Add separate rows when a provider changes pricing on a specific date.
- Check both Settings usage and Project Management Usage if a project-specific number looks wrong.

## Troubleshooting

- If the app estimate is lower than the provider dashboard, check missing pricing rows, cached token fields, and date range.
- If the app estimate is higher, check whether the wrong model row or effective date is being applied.
- If usage is still unpriced, confirm the provider/model name exactly matches the usage record.
- If provider data is delayed, wait a few minutes and refresh the view.
